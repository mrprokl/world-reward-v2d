# Hand specialists: automatic evidence, not a closed-cohort rescue

Audit date: 2026-10-04; publication/source cutoff: **2026-09-30**. Only bounded primary text and source metadata were read. No checkpoint, MANO asset, image, video, private label or Azure job was accessed. DexYCB v1's missing-hand failure remains CLOSED; a different detector is a new method requiring a fresh, frozen validation experiment, not a retry on that cohort.

## Decision

**WiLoR has the relevant independent hand detector, but none of these newly audited complete hand pipelines is presently cleared for this competition.** WiLoR's published detector is covered by the repository's non-commercial model notice; HaMeR and Dyn-HaMR require separately restricted MANO assets. MIT wrapper/source licensing does not clear their weights, transitive code or model assets. Native SAM 3D Body's existing `full` branch is the smallest technical option for full-person Track 1 clips, not a replacement detector for hand-only scenes, and retains the existing SAM-source eligibility question.

For dense hand evidence, first resolve rights for a **detector-only** implementation/checkpoint, then qualify automatic boxes and handedness before adding a 3D regressor or motion prior. A licensed WiLoR detector-only path would not require MANO; its present CC-BY-NC-ND checkpoint is not thereby relicensed. No candidate is adopted by this audit.

### What is actually automatic?

- **WiLoR:** the [native demo](https://github.com/rolpotamias/WiLoR/blob/fcb911312a38fa8badd30d9656a167485d61b8f9/demo.py) runs Ultralytics YOLO directly on the original image, `conf=0.3`; hand boxes and handedness classes do not require a detected person. It then regresses a MANO hand per padded crop. The paper separates fully convolutional localization from transformer reconstruction. The README publishes `detector.pt` and `wilor_final.ckpt` links; their immutable revisions, bytes, checkpoint hashes and detector-specific training lineage have **not** been independently verified here. The 2026 `--fast` path changes precision/layers and is not an equivalent default-model replay.
- **HaMeR:** the [default demo](https://github.com/geopavlakos/hamer/blob/3a01849f4148352e9260b69bf28b65d1671a4905/demo.py) detects COCO **persons**, runs whole-body ViTPose, and makes each hand box only when more than three hand landmarks exceed 0.5 confidence. Its `--full_frame` flag controls rendering, not a hands-only detector. The published reconstruction model is available through `fetch_demo_data.sh`; MANO_RIGHT.pkl is separately required. Its unchanged default pipeline does not solve missing-person coverage in close-up hand scenes.
- **Dyn-HaMR:** its [current README](https://github.com/ZhengdiYu/Dyn-HaMR/blob/fa9cd7412c205fd15ee4139c8caacf79bf6167e6/README.md) adds WiLoR's YOLO checkpoint, enhanced HaMeR tracking, VIPE/SLAM camera motion and interacting-hand optimization/prior. This is substantially more machinery than a detector substitution. It represents hands, not an object's shape/SE3 or the full MHR actor. The optional HMP prior requires 128-frame chunks; it does not authorize dropping remainder frames. Accurate-camera/RGB-D input routes must remain disabled for Track 1.
- **SAM 3D Body:** [estimator](https://github.com/facebookresearch/sam-3d-body/blob/b5c765a0d89d789985e186d396315e7590887b94/sam_3d_body/sam_3d_body_estimator.py) accepts the original full image plus optional automatic boxes/masks. `body` gives full-body output from the body decoder; `hand` runs a hand decoder on the supplied crop; `full` first estimates a person, obtains its own left/right hand boxes, refines each and fuses them. [run_inference](https://github.com/facebookresearch/sam-3d-body/blob/b5c765a0d89d789985e186d396315e7590887b94/sam_3d_body/models/meta_arch/sam3d_body.py), lines 1217–1238, proves that **hand mode is not an independent detector**. Default box acquisition is person-oriented. V2D already exposes body/full paths; its frozen vendored source `7c0d3b94ce97b28deb571b4e7fdfeb5b2158df80` must be checked separately from this newer upstream snapshot. Existing rejected hand experiments remain rejected.

## Licensing: do not conflate source, checkpoint and MANO

- Correct the blanket statement “HaMeR source is non-commercial”: its audited source LICENSE is MIT. This does **not** establish a commercial grant for every downloaded weight, MANO asset, training input or dependency.
- WiLoR's README explicitly puts its models under **CC-BY-NC-ND 4.0**. No separate OSI code grant was located at this revision. Ultralytics 8.1.34 uses [AGPL-3.0](https://github.com/ultralytics/ultralytics/blob/v8.1.34/LICENSE), an OSI license allowing commercial use with copyleft obligations—not a non-commercial license. Neither that license nor an MIT adapter cancels WiLoR checkpoint restrictions.
- Dyn-HaMR's MIT LICENSE conflicts with its README assertion that “code and model” are only for non-commercial research “i.e., MIT.” Obtain clarification of that conflict and separate pretrained-component rights before use; do not silently choose the more permissive sentence.
- [MANO's primary terms](https://mano.is.tue.mpg.de/license.html) grant non-commercial research use and restrict redistribution; commercial licensing is separate. Its page was read on the audit date (12,652 B, SHA256 `680491e5042d32c87b7730cf42ba4398b067f7fd7175331e9b1cbd98400cc187`), not established as a historical immutable legal snapshot. WiLoR/HaMeR/Dyn-HaMR full reconstruction depends on it.
- Kaggle Foundational 6.c's OSI/commercial-source requirement and the competition's specified pretrained-model/input exception are **different questions**. An exception for particular weights or inputs is not proof of a non-OSI inference-source waiver. Native SAM code/weights use custom SAM terms; official baseline usage alone does not resolve that source exception. See the existing license contract, not this audit, for the operative rule text.

## Coordinates, fingers and gauge

WiLoR/HaMeR consume original BGR images and automatic xyxy boxes; crop code pads/aspect-expands, horizontally flips left hands, converts crops to RGB and normalizes. Preserve the exact crop affine and original `[W,H]`; do not treat crop landmarks as full-image pixels or convert handedness into a second mirror.

Their demos restore full-image camera translation using a **learned weak-perspective scale plus assumed focal length**: `f_full = f_cfg / image_size_cfg * max(W,H)` and `t_z = 2*f_full/(box_size*pred_scale + 1e-9)`. Apply left-hand x correction and camera translation exactly once. Renderer/OpenGL flips are visualization operations, not an additional physical camera transform. These are not measured calibration or proof of absolute depth. A MANO hand mesh is not the MHR 18,439-vertex actor; stitching it in requires a separately tested anatomical/kinematic mapping and a common human/object gauge.

All three hand methods can infer plausible hidden fingers from learned priors; that is not observed visibility or calibrated uncertainty. Dyn-HaMR's occlusion infilling improves plausibility without making hidden joints measured. Monocular SLAM/VIPE camera reconstruction does not by itself certify metric hand-object depth. Aligned benchmark hand errors, smooth videos and Freihand PA-MPJPE are not absolute HOI/contact validation.

## Overlap and next falsifiable test

The audited [HaMeR training configuration](https://github.com/geopavlakos/hamer/blob/3a01849f4148352e9260b69bf28b65d1671a4905/hamer/configs/datasets_tar.yaml) explicitly includes `DEX-TRAIN` (406,888 records; SHA256 `20f7f22bec502f5479832ec0f9a3a2444d0fbe2035801d0168d22173e4823a60`). [WiLoR's configuration](https://github.com/rolpotamias/WiLoR/blob/fcb911312a38fa8badd30d9656a167485d61b8f9/pretrained_models/dataset_config.yaml) also includes `DEX-TRAIN`, HO3D, H2O3D, InterHand, ARCTIC and others (SHA256 `9bb36eed313451b118ed76885a0bdaacbe6d6301f22ce2b19f9411c136b3c5b8`). This is overlap-risk evidence, not proof of the exact checkpoint's sample membership or detector training set. Neither DexYCB nor a held-out subject is automatically leakage-free. Dyn-HaMR inherits such component risks; challenge overlap remains unverified for every candidate.

1. **Before any model job:** use tiny data-free tests for original/crop roundtrip, left/right conventions, multiple hands, empty detections, image borders and full-frame retention. Synthetic boxes/landmarks test plumbing, not learned detection quality.
2. **Before new expensive tracking:** freeze a genuinely fresh licensed validation cohort/split not selected from the failed DexYCB clips; document model-training overlap. Compare generic `hand.` and one cleared specialist on the same RGB, automatic instance bank and fixed downstream policy. Include every frame, absent hands, distractors, handedness errors, missed/merged masks and wrong-instance association. Freeze coverage/error thresholds on a separate calibration split before opening validation values; do not choose prompts, confidence or nearest-hand rules from challenge failures.
3. **Only if detector evidence qualifies:** add dense landmarks as an observation factor, never as an automatic “manipulated object” label. Test persistence/co-motion versus distractors and abstention independently. Full-person clips can test existing native body/full branches under their unchanged shared K/identity/object gauge. Any claimed 3D improvement additionally needs absolute hand-object/actor metrics with missing frames retained, no oracle scale or per-frame alignment.

**Stop gate:** unresolved source/model rights or inadequate automatic candidate coverage stops the specialist experiment before tracking/3D optimization. No new compatible hands-only detector, metric-gauge solution, finger-occlusion guarantee or SOTA HOI win is established here.
