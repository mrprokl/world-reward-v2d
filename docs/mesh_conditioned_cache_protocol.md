# Fixed-chart compiler: exact cached implementation regression

The numerical algorithm has passed four procedural geometry controls, but its
full physical-coordinate decode on every proposed collapse needlessly scales
with source size. This experiment changes implementation, not geometry, cost,
queue order, placements, chart, serialization or volume thresholds.

Freeze the [protocol](../configs/mesh_conditioned_cache_protocol_v1.json).
Recompile the exact previously qualified source and require its measured binary
identity. Compile the new opt-in implementation with `WR_CONDITIONED_CACHE=1`.
Initialize the physical cache using the same inverse chart; update only both
endpoints of an actually committed collapse. Independently decode the final
result and compare every vertex with its birth-indexed cached position.

Before any paired call, authenticate and qualify the exact four previously
successful sources. Require eight successful real-collapse arms and identical
input OBJ, output OBJ, full mapping JSON, counters and physical candidate,
F32/GLB, default-eight weld, official packing and once-only metric-stage evidence.
No failed cohort is replayed. Any mismatch, timeout or unavailable execution
closes the regression; do not retune or fall back.

Use the existing offline Azure CPU image: two compilations at most600s each,
each geometry call at most450s, inclusive5400s and10s receipt-publication grace.
Only complete native and host PASS permits retention of the fast binary0555,
receipts0444 and result directory0555. Remove an owned retained binary on failure.
This is a bounded implementation regression, not universal equivalence, a
production-mesh validation, HOI accuracy evidence or a CARI4D victory.
